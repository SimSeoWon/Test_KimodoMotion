### 1.2 스탠스와 좌우 반전

NS 의 스탠스는 **좌(Left)·우(Right)·중앙(포창, Center)** 셋이다. 스탠스를 바꾸면 발과 손(창을 쥔 위치)이 함께 바뀐다.

- **공격은 왼쪽 스탠스 기준 한 벌만 만든다.** 오른쪽 스탠스의 공격은 같은 몽타주를 좌우 반전해 재생한다
  (NS `Request.bMirrored = 스탠스 == Right`, 애님 BP 의 Mirror 노드).
- 공격이 아닌 동작(대기·보법·스탠스 전환)에 반전을 쓸 수 있는지는 NS 애님 BP 구성 전이라 **미정**이다 — 표에 좌·우를 따로 적되,
  반전으로 대체할 수 있으면 왼쪽만 만든다.
- 중앙(포창)은 창을 몸 안으로 안아 쥐는 전방위 방어 자세라 반전 대상이 아니다.

### 1.3 움직임의 느낌 (애니메이션 제작 참고)

- 체중은 **뒷발**에 둔다. 검도는 뒷발에 실은 체중으로 앞쪽으로 **치고 나가는** 느낌, 유수(창술 신법)는 **계속 뒷발에 체중을 둔 채**
  여러 방향으로 유연하게 움직이는 느낌이다. 병기별로 어느 느낌을 따를지는 정하지 않았다(창은 유수, 짧은 병기는 검도 쪽이라는 제안만 있다).
- 락온 교전의 기본 발놀림은 **수리앗시(스쳐걷기)** — 발을 높이 들지 않고 바닥을 스치듯 옮긴다. 뒷발 뒤꿈치는 살짝 든다.
- 궁보(앞다리 굽힘·뒷다리 폄, 찌르기 종착)와 마보(다리를 벌려 하체 고정, 휘두르기·방어 종착)는 **동작의 종착 자세**다.

### 1.5 창과 손

- Kimodo/SOMA30 에는 **무기와 손가락이 없다.** 창은 UE 에서 소켓으로 붙이고, 손은 **양손이 창대 위에 있는 위치**를 키포즈 제약으로 잡는다.
  두 손 사이 간격이 창대 길이 방향으로 일정해야 한다(창이 휘어 보이지 않게).
- 손가락 쥠은 UE 쪽 포즈로 처리한다(SOMA30 에 손가락 자유도가 없다).

### 1.6 이어 붙이기

- 같은 스탠스의 **대기 자세를 시작·끝 키포즈로 고정**한다(웹 UI 포징 모드에서 저장 포즈로 만들어 재사용). 그래야 스텝을 연속으로
  이어도, 스텝 뒤 공격으로 넘어가도 자세가 튀지 않는다.
- 스텝은 끝 자세 = 시작 자세를 보폭만큼 평행 이동한 것이어야 한다.

### 1.7 Kimodo 로 만들 때의 주의

- 프롬프트는 **짧고 동작 중심**으로 쓴다(장문·연출 묘사는 말단 관절을 깨뜨린다 — `history/2026-09-17_prompt-length-artifact-and-blender-diagnostics.md`).
- 짧은 클립(스텝 ~0.45초)은 1~2초 분량을 생성해 한 동작 구간만 잘라 쓰는 편이 안정적일 수 있다 — 실측으로 정한다.
- NS 로 넘기려면 **UE 리타겟 팔 꺾임**이 먼저 풀려야 한다(`HANDOFF.md`).

## 3. 넘기는 방법

1. 이 리포에서 생성 → 웹 UI 미리보기(마네킹 Quinn)로 1차 확인 → 검수 기준 확인.
2. UE 리타겟으로 마네킹 AnimSequence 생성(**팔 꺾임 해결이 전제**) → NS `Content/` 의 애니메이션 폴더로 이관.
3. 보법 스텝은 NS 에서 루트 궤적으로 거리 커브를 붙이고(Distance Curve 모디파이어) 제자리 재생으로 설정한다 — NS 쪽 작업(#692 S3).
4. 스탠스 전환은 「전환 완료 프레임」을 함께 넘긴다.
