### 현재 구조와 검증 결과

- NVIDIA 공식 구현은 `nv-tlabs/kimodo`. 현재 WebUI는 `localai-org/kimodo.cpp`의 사용자 포크를 실행한다. 두 프로젝트를 같은 것으로 설명하지 않는다.
- C++ 엔진을 즉시 교체해야 한다는 결론은 아니다. 지원 기능과 요청/결과 계약을 정리하고 공식 구현을 비교 기준으로 삼는 방향을 제안했다.
- Python 테스트 **31개 통과**, Node FK/IK 테스트 **1개 파일 통과**. 임시 데이터와 모의 프로세스로 추가 결함 재현.
- 높은 우선순위: 상주 워커를 둔 채 단발 추론을 추가 실행하는 경로, 표시 캐릭터의 뼈 비율이 생성 제약에 들어가는 문제, 히스토리 불러오기의 포즈·CFG 복원 누락.
- 그 밖에 프레임 범위 불일치, G1 등을 노출하지만 SOMA30으로만 내보내는 문제, 공간/가중치 무시, 미리보기 파일을 기본 다운로드로 제공하는 문제, 런처의 무조건 포트 소유 PID 종료 등을 확인했다. 재현·코드 위치·수정안은 보고서 W01~W09.
- 공식 root2d/전신·손발 제약, 접지·제약 후처리와 현재 WIP의 동등성은 검증되지 않았다. SOMA 내부 30관절은 정상이며 공식 77관절은 공개 표시/출력 확장이다.
- **실GPU 추론·공식 Python parity·브라우저 E2E·UE 임포트는 이번에 하지 않았다.** CMake의 `KIMODO_BUILD_TESTS=OFF`도 그대로다.

### 작업 트리·서브모듈 상태 (2026-09-27 실측)

- 루트 HEAD `aced544` (`main`), 로컬 원격 추적 기준 `origin/main`보다 1커밋 앞섬. 원격 fetch는 하지 않았다.
- 이번 변경은 `HANDOFF.md`, 위 검증 보고서, 이전 인계 아카이브의 **미커밋 문서 변경**이다. 애플리케이션·서브모듈 코드는 수정하지 않았다.
- `.claude/settings.local.json`이 미추적으로 표시됐다. Git 전역 ignore 접근 권한 경고가 있으므로 다른 실행 환경에서는 표시가 달라질 수 있다. 건드리지 않는다.
- 서브모듈 실제 포인터는 **`88cbfbc`**, 현재 브랜치와 로컬 `origin/motion/main`도 같음. `811eceb`의 후손이며 추가 변경은 데모 로그 무시다. 이전 인계의 `811eceb` 기록보다 최신이다.
- GGML 실제 HEAD는 고정값 `8c63e709`와 일치한다. 서브모듈 추적 변경 없음.
- `origin`=사용자 포크, `upstream`=C++ 포팅판. 원본 갱신은 `motion/main`에 **merge**하며, 포인터 변경 전 원격 포함·기존 핀의 후손 여부를 확인한다(README 규칙).

### 보존할 로컬 상태와 이전 성과

- `KimodoTestbed/`는 여전히 비어 있다. 리타겟 재개 전 `KimodoImportLibrary.*`/`Kimodo.ImportIK` 소스 위치를 확인해야 한다.
- 로컬 SOMA RP v1.1 GGUF, 텍스트 인코더 번들, 빌드 실행 파일, 생성 결과 3개 디렉터리가 존재한다. 설치/정리/교체를 자동으로 하지 않는다.
- Quinn 마네킹의 A→T 포즈 변환과 텍스처 색 미리보기는 이전 세션에서 사용자가 확인했다. 원본 FBX/PNG와 가공 바인딩은 git 밖에 둔다.
- 바인딩 재추출 후 `webui/static/tpose_<id>.glb`와 결과의 `preview_v2_<id>.glb` 캐시가 자동 무효화되지 않는다. 이번에 캐시/바인딩은 수정하지 않았다.
- NS 조건: [`docs/ns-animation-requests.md`](docs/ns-animation-requests.md). 첫 대상 F1 밀어걷기 전진 1보(NS #692 S3). 리타겟 팔 꺾임·루트 이동 보존은 후속 검증 사항이다.
- 이번 검증 중 서버·Unreal·Claude·추론 워커를 시작/종료하지 않았다. 다음 세션에서는 프로세스와 포트를 새로 조회한다.
