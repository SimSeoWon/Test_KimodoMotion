# 포즈 에이전트: 해부학 각도 명령 + Python 검증 (속도 개선)

- 날짜: 2026-09-27
- 요청: "LLM으로 조절하는 게 너무 느리다" → "각 부위 조절·검증을 Python에서 데이터 기준으로(예: 무릎 0°~130-150°, 과신전 −5°, 한 방향만)".
  사용자 결정: 신뢰할 만한 해부학 참고값으로 진행. 추가 요구: 부위별 순차 검증이 부모 관절 때문에 교착되던 문제를 피할 것.

## 원인 실측

포즈 에이전트 시간의 거의 전부가 모델의 생각(thinking) 토큰이었다 — 쿼터니언·좌표를 직접 계산하고 검산하게 한 프롬프트 때문.
같은 요청("엉덩이를 뒤로 빼고 자세를 낮춰", 동일 프롬프트 6,877자)의 effort별 결과:

| effort | 시간 | 출력 토큰 | 비용 |
|---|---|---|---|
| low | 38초 | 3,028 | $0.15 |
| medium | 92초 | 9,851 | $0.22 |
| high | 158초 | 14,297 | $0.22 |

당일 사용자의 실제 요청은 149초(effort 미지정).

## 구조

- `webui/joint_limits.py` — 가동 범위 표와 출처. AAOS(*Joint Motion: Method of Measuring and Recording*, 1965)의 수동 ROM:
  목 굴곡/신전 45/45·측굴 45·회전 60, 어깨 굴곡 180·신전 60·외전 180·내전 40·외회전 90·내회전 70, 팔꿈치 150, 아래팔 80/80,
  손목 80/70·요측 20·척측 30, 고관절 굴곡 120·신전 30·외전 45·내전 30·회전 45/45, 무릎 135(사용자 130~150 → 150 상한), 발목 배굴 20·저굴 50·내번 35·외번 15.
  과신전 −5°는 사용자 지정(출처 미확인). 흉요추·쇄골·손목 트위스트는 근사값이라 경고만.
- `webui/pose_anatomy.py` — 표준 라이브러리만으로 쿼터니언·SOMA30 FK·측정·검증·편집.
  볼 관절(어깨·고관절·목·척추·발목·손목·쇄골)은 **스윙(해부학적 중립 방향에서 들린 각도, 네 평면 한계로 만든 타원 원뿔) + 트위스트(중립에서의 최소 스윙 기준)** 로 재서
  오일러 순서 문제(코드먼 역설)를 피한다. 어깨는 가슴 기준(쇄골+상완)으로 재어 견갑상완 리듬(Inman 2:1)을 자연히 포함한다.
  무릎·팔꿈치는 힌지: 축 밖 회전 10° 초과 = "옆으로 꺾임", −5° 미만 = "반대로 꺾임".
  접지: 발목·발끝·발뒤꿈치(편집기와 같은 유도점) 2cm 이상 지면 아래면 오류. 두 관절 근육 결합(무릎 편 채 고관절 굴곡 90° 초과)은 경고.
- **발목 체중 부하 규칙**: AAOS 배굴 20°는 비체중 부하값이라 평범한 마보 자세(무릎 70°)도 24°로 오류가 났다. 발이 바닥에 닿아 있으면 45°까지 허용
  (체중 부하 런지 테스트에서 30° 미만을 제한으로 본다는 검색 요약만 확인, 원문 2편은 403으로 못 엶 → 근사값으로 표기).
- 축·부호는 추측하지 않고 FK 결과로 테스트에 고정(`pose_anatomy_test.py` 15개): 무릎 굴곡 → 발목이 무릎 뒤, 고관절 외회전 → 왼발끝 X > 발목 X(CLAUDE.md의 팔자 규칙),
  발목 내번 → 발등이 바깥, 어깨 외회전 → 굽힌 아래팔이 바깥, 목 굴곡 → 눈이 앞·아래 등.
- `webui/pose_ops.py` — LLM 출력 스키마와 적용. LLM은 `{"joint":"left_knee","mode":"set"|"add","angles":{"flexion":60}}`,
  골반 `translate_m`, 손발 끝 이동(IK)·`turn_out_deg`, `keep_planted`만 낸다. Python이 적용 → 두 뼈 IK(힌지 굴곡은 이분법, 무릎은 발끝 방향을 따라감) → 검증.
  오류면 위반 수치를 붙여 **한 번만** 재요청, 그래도 오류면 거절. 요약 끝에 Python이 잰 수치(골반 높이·발 간격·무릎 각도)를 붙인다.
- **교착 방지**(사용자 지적): 명령은 전부 적용한 뒤 **최종 자세만** 검증한다. 손발 이동은 편집 시작 위치 기준이라 앞 명령의 중간 상태에 끌려가지 않는다
  (처음 구현은 중간 상태 기준이어서 "무릎 170°→발 이동→무릎 30°" 순서가 발을 공중으로 보냈다 — 테스트로 고정).
- 연결: `PoseCliRuntime(schema, effort)`. 기본 런타임은 각도 명령 스키마 + `--effort low`(`KIMODO_POSE_AGENT_EFFORT`로 변경). 편집기가 스냅샷에 `bone_state`를
  보내면 이 경로, 없으면 기존 쿼터니언 경로(`LEGACY_POSE_CLI_RUNTIME`, 필요 시 기동). 결과의 `bone_state`는 편집기가 IK 재해석 없이 그대로 보여준다.
- 처음 구현의 무릎 방향 기준점이 IK 전 무릎이라 무릎이 안쪽으로 무너졌다(발끝 0°에 무릎 −16°) → 엉덩이-발목 중간점에서 발끝 방향으로 잡아 3° 이내.

## 검증

- 단위 테스트: 해부학 15 + 명령 적용 10, 전체 Python 78개·Node 3개 통과.
- 실제 Claude(sonnet, effort low, 요청마다 새 CLI): "자세를 낮춰" 7.7초 → "양발을 넓게" 7.7초 → "팔자로" 8.6초 → "오른손을 머리 위로" 9.0초, 모두 1회 통과, 요청당 $0.07~0.12.
- 헤드리스 Chrome + 별도 서버(8190): Quinn 표시 상태에서 "엉덩이를 뒤로 빼고 자세를 낮춰" 6.8초, "양 발을 넓게 벌리고 발끝을 바깥으로 팔자로 벌려" 4.8초,
  편집기에 정확한 뼈 상태 반영, 이력에 측정 수치 표시, 페이지 오류 없음.
